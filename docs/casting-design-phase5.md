# 第五阶段：工程回答、历史追问与恢复

业务数据库迁移由用户后续单独执行。本阶段新增 0012 迁移，仅扩展 qa_turns 的 outcome 检查约束，允许 casting_design；不改动旧 outcome，不新建消息角色、文档来源或工具消息表。0010/0011 的普通 RAG 继续可用；开启 casting_v1_v3 正式回答需要 0012。

工程回答使用独立 CastingAnswerDraft，复用 answer_draft snapshot、generation/result artifact 和现有原子消息发布。草稿保存有界正文、事实引用、来源 ID/hash 和摘要方式，不保存完整输入/推荐 JSON。普通 AnswerDraft 的 Document 来源约束保持不变。

模型只返回 fact_refs 的选择与顺序，后端从已核验 recommendation 构造中文事实段落。正文不接受模型提供的数值、单位、候选、通过状态或自由文本替代值。状态、推荐身份、规则版本、输入来源和待补证据始终由服务器渲染。非法模型内容使用确定性模板并记录 template；上游不可用/超时保留 run，显式重试只重做解释。模型调用不持有业务事务。

发布前在事务外重新读取并核验结果 SHA，重新渲染草稿形成校验凭据；发布事务内再次核验会话、turn/attempt、route/tool/generation/result 的祖先关系、run/result 文件和 hash，并比较整个已核验草稿。无输入/来源歧义说明绑定有效路由；新计算只能引用本轮 run，历史解释只能引用同会话更早的已完成计算结果。已发布历史读取业务消息和来源元数据，不再次运行模型或引擎。

摘要/模型失败后的新 attempt 继承已经保存的路由意图和 run 来源，不重新选输入/规则或改变计算路由。中断的同 attempt 继续使用持久化 stage/snapshot。忙、存储不可用和模型异常可显式重试；确定性输入/策略/完整性错误释放会话并禁止自动重算。已完成但没有候选、准入失败和引擎失败生成受控业务说明，保留审计记录。

历史追问可在路由中选择 source_run_id 和可选 candidate_rank。从完整推荐文件读取该排名候选，仍保留程序真正的推荐 ID，不把被查看的候选改成推荐方案。候选超出实际结果时拒绝该路由。

RAG 查询改写只选择普通问答的已完成轮次，工程轮次通过上述 run 引用读取。工程方案长正文不占用原有 RAG 历史预算，也不被作为知识库文档来源；原有字节上限、完整消息对和来源校验保持不变。

公开 API 接通 question + casting_input_file_id；功能与图版本均启用后才接收工程输入。现有 v2 请求按保存版本恢复。返回和历史增加可选 casting 元数据、输入引用，正文沿用现有聊天消息。前端附件控件仍属第六阶段；本轮不改 .env 或启用业务实例。

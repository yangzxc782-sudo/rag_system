# 第六阶段：聊天工程附件与结果展示

本阶段沿用现有同步聊天与明确重试机制。新增单 JSON 附件控件、独立工程 API 客户端、工程结果来源/状态及字段错误展示；不进入知识库文档上传链，不引入 UI 或 Markdown 依赖。

附件上传保留原 File 字节，只在内存持有。发送前上传完成，turn 只提交冻结的 casting_input_file_id。上传失败重试沿用原上传 request_id；聊天网络不确定先查询原请求，重试保持原附件及参数。切换会话取消客户端等待并丢弃临时选择，不取消后端已有运行。pending 兼容旧记录，只保存允许的请求字段。

现有接口补充两项只读元数据：文件列表增加 reusable_input，由现有 select_input 查询真正的最近明确选定且已准入文件；历史消息增加 casting_input_filename，为该消息 requested/effective 输入文件名。二者不修改输入选择算法、不新增迁移，避免前端从分页历史猜测复用对象。

工程附件区域按需加载文件列表；默认普通问答不额外请求工程接口。文件上传仅代表结构检查通过，工程准入仍由计算程序完成。移除选择只取消本轮附件，不删除后端文件；无新附件时由后端按既有规则决定是否复用。历史文件可以明确选定后随新问题发送。

正文继续以现有安全文本方式展示，明确工程状态、输入来源、规则版本与运行编号。显示受控 field_path/error_code/message 列表，支持从会话绑定 API 下载原 recommendation。复杂方案卡片与渲染表格留待后续。

验收包括附件与普通问题、历史/分页/刷新、跨会话迟到响应、取消/重试上传、网络中断/202/显式聊天重试、非法输入与无候选、原引用与证据删除提示。业务库迁移、实际配置启用和真实外部服务完整验收仍不在本轮执行。
